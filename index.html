Output Receipts

A discovery aid that connects the data NCI's awards have shared back to NCI's catalog. Public data only; runs without AI.

For a set of NIH awards, Output Receipts follows each award to its papers, reads what each paper says it deposited, checks each deposit against the repository's own record, and writes the results as candidate rows for the Index of NCI Studies (INS) and as a receipt for each award. It is a starting point for curation, not a replacement for it. This run covers the 589 new R01 awards NCI made in fiscal year 2024.

What is looked up

  • The record exists and is public: 1,283 of 1,329 identifiers checked. 5 more exist behind an access request; 41 do not resolve, 21 of them still private.
  • The repository's record cites the paper, names the award, or lists a submitter whose name matches an author (744 of 1,012 datasets).
  • NIH RePORTER links the paper to the award.
  • INS lists the dataset, or does not.

Exact, and anyone can check each one in a click.

What is inferred, and what is not known

  • Inferred from wording: whether a deposit is the paper's own or data it reused. The sentence is in every row.
  • Not determined: 253 of 2,086 papers have no open full text, and the tool does not guess.
  • Not claimed: which award paid for a dataset when a paper cites several; rows say "associated with, per RePORTER", as INS does for publications.

How it works

  1. Awards to papers. NIH RePORTER's award–publication links, with INS's rule excluding papers published more than a year before the award started.
  2. Papers to full text. Open-access XML from PubMed Central and Europe PMC.
  3. Statements and identifiers. The data availability statement, and identifiers for more than 25 repositories.
  4. Own or reused? Judged from the sentence: “generated in this study… deposited in” versus “downloaded from”, “previously published”, TCGA.
  5. Link and record check. Each deposit is looked up in its repository: does it exist, is it public, and which paper, award and people does the record name?
  6. Outputs. Candidate rows in INS's format with a tier, and a receipt per award.

What it is good for

  • Finds deposits in any repository, from the authors' own statements.
  • Hands curators rows with evidence and a stated confidence, so checking replaces searching.
  • Transparent rules and public lookups: free, repeatable, no credentials, no AI needed to run.
  • Works for any NIH Institute, activity code or fiscal year.

Limits

  • Reads only open full text; not supplementary files.
  • Own-versus-reused is a judgment from wording; tier 3 is where it is weakest.
  • Some repositories (dbGaP, EGA, MassIVE, GitHub) have no record the tool can compare yet. dbGaP is the weakest: INS attributes 28 of the 38 dbGaP studies found here to earlier papers, so they are probably reused consortium data.
  • Reports what is findable, never compliance with a data sharing plan.
  • Dead and private links are counted here but listed only in the local outputs, for the investigator to fix.

Use of AI

Running the tool requires no AI. An AI coding assistant helped write the code; AI models served as the blind reviewers for the accuracy checks; and AI labelled the category of papers the rules could not categorize, which does not affect the dataset rows. Details: AI_REVIEW.md.
